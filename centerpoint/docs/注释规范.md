# 代码注释规范

本规范用于指导 CenterPoint 代码库（`det3d/`、`tools/`、`configs/`）的注释编写，保证注释风格统一、内容准确、可维护。

## 1. 总体原则

- **语言**：所有注释统一使用中文。
- **同步性**：注释必须与实际代码一致；修改代码后必须同步更新注释。
- **准确性**：只描述代码真实做的事，不臆测、不写未实现的抽象。
- **简洁清晰**：避免冗余和照抄代码本身的表述，重点解释「为什么」和「做了什么」。
- **不改逻辑**：注释改造仅新增/修改注释与 docstring，不得改动任何运行逻辑、参数默认值或 API 签名。

## 2. 文件级注释（模块 docstring）

放在文件开头（`import` 语句之前或之后均可，推荐紧跟文件头 shebang/编码声明后、import 前）。

要求包含：
- 模块功能概述（一句话说明用途）；
- 主要类/函数清单；
- 设计思路（关键数据结构或流程）；
- 与其他模块的关系（被谁调用、依赖谁）。

## 6. 易混淆点注释

以下场景必须补行内注释说明原因：
- 坐标/尺寸/角度（yaw）的约定切换；
- 索引展平公式（如 `ind = y * W + x`）；
- 张量维度排列（NCHW 与 NHWC 互转）；
- 数值稳定性处理（log/exp/sigmoid 截断、softmax 分母加 eps）；
- 稀疏目标 gather/mask 处理；
- 多进程/分布式相关逻辑。

## 7. 论文联动注释规范（Center-based 3D Object Detection and Tracking）

本项目是 CVPR 2021《Center-based 3D Object Detection and Tracking》(arXiv:2006.11275) 的官方实现。核心算法模块的注释必须同时说明「代码实现」与「论文理论」的对应关系。

### 7.1 论文章节速查

- Sec. 1 引言：为什么用中心点表示代替 3D box、旋转不变性动机。
- Sec. 3.1 Center heatmap（中心热图）：backbone 输出 BEV 特征 → CenterHead 预测 K 通道热图；GT 中心经下采样映射后以 2D 高斯软化。
- Sec. 3.2 targets（回归目标）：offsets(2) + height(1) + size(3) + yaw(sin,cos)(2)，可选 velocity(2)。
- Sec. 3.3 losses（损失）：penalty-reduced Focal Loss 用于热图；L1 回归损失仅在 GT 中心位置计算。
- Sec. 3.4 two-stage refinement：从估计 box 的面中心采样点特征，经 MLP 预测 IoU 置信度与 box 精炼。
- Sec. 3.5 velocity & tracking：速度回归 + 贪心最近点匹配实现跟踪。

### 7.2 标注方式

在关键实现处用行内注释或 docstring 标注论文章节与公式编号，例如：

```python
# 论文 Sec. 3.1：将 GT 3D 中心投影到热图网格，并用 2D 高斯软化中心监督（公式(1)）。
# 论文 Sec. 3.3：热图使用 penalty-reduced focal loss（公式(2)）。
```

### 7.3 论文-代码映射（核心）

| 论文概念 | 代码位置 |
| --- | --- |
| center heatmap（中心热图） | det3d/models/bbox_heads/center_head.py（SepHead 的 hm 分支） |
| 高斯半径 / 热图绘制 | det3d/core/utils/center_utils.py（gaussian_radius、draw_umich_gaussian） |
| 回归目标构造（AssignLabel） | det3d/datasets/pipelines/preprocess.py |

## 8. 禁止事项

- 不添加 emoji；
- 不使用英文注释（除非是公认专有名词）；
- 不复制源码逐行翻译；
- 不添加与代码无关的 TODO、版权、作者等延伸信息（除非原文件已有且需保留）；
- 不为了注释而改动 import 顺序、行内变量或代码结构。
